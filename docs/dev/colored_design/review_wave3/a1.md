5. **Wrong factorization cannot be certified.**
   - A·B is a rearrangement of L_p's own word using only `rungs_commute` swaps.
   - c_diag(p) = c_diag(a)·c_diag(b) is only a success heuristic: it makes the identity-coset matrix a Kronecker

   - If `rungs_commute` were wrong, or a 1-dimensional Hom^0 were not an isomorphism, certify_closure would fail with
     a visible Exhausted. It would never produce a wrong basis.
   - Downstream uses a Gram matrix computed from the generators (cclose.rs:442ff), so the order of the products does
     not matter.

7. **Census exhaustiveness.** `reduced_words(s, t, 5, 400_000)` visits 1+12+144+1 756+21 688+269 776 = 293 377 words

## Findings

### m1 (minor, test-coverage). tests/leaves.rs does not check that the product rule produced the maps

**Where:** tests/leaves.rs:52 and leaves.rs:296-301.

**What happens:**
- With `product_first = true`, a failed `product_closure` is silently swallowed (`if let Ok(r)`), and
  `ProductClosure::closure` falls through to the inner chain.
- The test discards the returned `SearchStats` (`let (ms, _)`), so it never checks `st.detect == "stage0-product"`.

**Failure scenario:**
- M5c_report.md (revm5, lines 163-166) shows the production chain now certifies 3 of the 5 product types:
  1,0,2/2,0,1/0,3,0, 0,3,0/1,0,2/2,0,1 and 1,2,0/0,0,3/2,1,0.
- A regression in `product_inner` or `swap_map` (wrong Kron side, wrong iso orientation, a dimension-≠1 refusal)
  would then make those 3 types pass the test through the chain. The test would get slower and stay green, with the
  Stage 0 code path untested.
- `m4c stage0` has the same weakness. Its "certified 5/5" count does not say which route certified each type; the
  route can currently be inferred only from `K` records in the layer-A files.

**Fix:** assert `st.detect == "stage0-product"`, or call `pc.product_closure(..)` directly and certify its output. In
m4c, print the provider summary (or `detect`) per type.

### m2 (minor, test validity). The G-L1 Deodhar gate is less independent of schur.rs than claimed

**Where:** dcoset.rs:16-18 and 157-170; A1_report §1 ("this code does not share anything with `Schur::rung`").

**What is shared:**
- `step_terms` takes its defects from the same `Table::lmax`/`Table::lmin` (schur.rs:135-157) as
  `Schur::ensure_rung_image` (schur.rs:961, `lq - s.lmax()`) and `merge_table` (schur.rs:802, `nt.lmin() - t.lmin()`).
- The extra ascending term −ℓ(LR to)+ℓ(LR u) equals −Σ_i x_i·t_{i,rec}. That is exactly the shift between the
  one-sided `gauss_v` and schur's symmetric q-binomial. So, term by term, the two G's are the same expression.
- The E/F split order was copied from schur (dcoset.rs:103).

**What G-L1 does and does not test:**
- It does validate the x-enumeration, the split conventions and the Gaussian binomials.
- It cannot detect an error in `Table::lmax`, which no G-L1 test checks independently. `lmin` is checked, by
  `perm_len(min_perm)` at tests/dcoset.rs:194.
- The two "Lemma 8.7" rows add no independent evidence:
  - Σ_t fwd·back at any level = c_id(forward.last) = c_id(ladder_char) = c_diag by schur's definition (schur.rs:1361).
  - The extension row is the identity b_p·ρ = Σ_q [expand(b_p·ρ)]_q·b_q, with term_mult = expand(b_p·ρ)
    (schur.rs:1389-1400).

**Impact:** none on results today. dcoset feeds only the census and `apply_labels` in Stage 0. It will matter if A2
relies on dcoset's G as an independent check of step dimensions.

**Fix:**
- Add an independent check of ℓ(p̄) and ℓ(p_), for example brute force over S_K: group permutations by
  `table_of_perm` and take the max/min inversion count. K = 9 is 362 880 permutations, which is fast.
- Or compare G at v = 1 against per-level coset counts from `sexpr::FlowIndex`.
- Drop the independence wording.
